# ui-hierarchy — 정보 위계와 보조 설명 배치

좋은 화면은 **읽을 게 적다.** 문구를 잘 쓰는 것(ux-writing-kr)보다 먼저, 그 문구가 화면에 있어야 하는지, 있어야 한다면 어느 층에 둘지를 정한다.

## 1. 한 화면, 한 가지 일

- 화면마다 사용자가 하려는 일 하나를 적는다. 예: 메인은 "오늘 볼 종목 고르기", 상세는 "이 종목 연기금 흐름 확인".
- 그 일에 필요 없는 정보는 지우거나 다음 층으로 내린다. 토스는 이를 "하나의 화면은 하나의 메시지"라고 부른다.
- 사용자가 방금 스스로 고른 것(필터 조건 등)을 화면에 다시 읽어주지 않는다. 버튼 상태가 이미 말해준다.

## 2. 위계는 3단계까지

NN/g(2024)의 시각 위계 정의를 따른다. 크기, 색·대비, 묶음(근접·공통 영역) 세 가지로 순서를 만든다.

- 글자 크기는 **크게·보통·작게 3단계**만 쓴다. 단계가 늘면 위계가 흐려진다.
- 강조색은 한 화면에 **한 가지 의미**만. 예: 빨강 = 연기금 매수 금액.
- 굵게는 숫자·핵심 값에만. 문장 속 굵게는 최소화.
- 강조가 여러 개면 아무것도 강조되지 않는다. 화면마다 "가장 먼저 눈에 들어와야 할 것"을 하나 정한다.

## 3. 보조 설명은 사다리 순서로 푼다

설명이 필요해 보이면 위에서부터 차례로 시도하고, 앞 단계에서 해결되면 멈춘다.

1. **지운다.** 없어도 사용자가 할 일을 할 수 있으면 뺀다.
2. **라벨을 고친다.** 설명이 필요한 라벨은 대개 라벨이 나쁜 것이다. 라벨 자체를 뜻이 통하게 바꾼다(ux-writing-kr).
3. **쓰이는 자리로 옮긴다.** 설명을 그 정보가 영향을 주는 곳에 둔다. 예: 필터별 과거 성과는 메인이 아니라 필터 패널 안에. NN/g의 progressive disclosure: 처음엔 핵심만, 부가 정보는 요청할 때.
4. **토글팁(ⓘ)으로 접는다.** 용어·계산 기준처럼 "궁금한 사람만 볼" 내용. 눌러서 열고, 바깥을 누르거나 Esc로 닫는다.
   - 호버 툴팁은 터치에서 안 보이고 존재도 안 드러난다(NN/g 툴팁 가이드, Inclusive Components). **필수 정보는 절대 툴팁에만 두지 않는다.**
   - 한두 문장까지. 길면 바텀시트나 별도 화면.
5. **처음 한 번만 보여준다 (코치마크).** 드래그·핀치처럼 보이지 않는 제스처는 처음 쓸 때 한 번 짧게 알려주고, 본 뒤에는 숨긴다. 매번 떠 있는 안내문은 소음이 된다.
6. **어포던스로 대신한다.** 글 대신 커서 모양, 선택 영역 하이라이트, 드래그 핸들, 상태 버튼(1개월/3개월/전체)처럼 **보면 알게** 만든다.
7. **바텀시트·다이얼로그.** 여러 문단이 필요한 설명(방법론, 용어 모음)은 따로 연다.

## 4. 형태별 쓰임새

| 형태 | 언제 | 주의 |
|---|---|---|
| 라벨 개선 | 항상 첫 선택 | 라벨이 설명보다 길어지면 3단계로 |
| 인라인 보조 문구 (작은 회색 글) | 입력 형식처럼 안 보면 틀리는 정보 | 한 줄. 모든 항목에 붙이지 않는다 |
| 토글팁 ⓘ | 용어 뜻, 계산 기준, 가정 | 필수 정보 금지. 터치로 열려야 함 |
| 호버 툴팁 | 아이콘 버튼 이름, 차트 값 | 마우스 전용이라 보조로만 |
| 코치마크 (1회) | 숨은 제스처, 새 기능 | 1회 후 다시 안 뜨게 저장. 닫기 쉽게 |
| 빈 화면 안내 | 결과 0건 | 이유 + 다음 행동 |
| 바텀시트/다이얼로그 | 긴 설명, 방법론 | 본 화면 흐름을 막지 않게 |

## 5. 점검 (화면 하나 끝낼 때)

1. 이 화면의 일 하나를 한 문장으로 말할 수 있나?
2. 처음 3초에 눈이 가는 곳이 그 일에 맞나?
3. 글자 크기가 3단계를 넘나? 강조색이 두 가지 뜻으로 쓰이나?
4. 사용자가 이미 아는 것(자기가 고른 조건, 제목 반복)을 다시 말하나?
5. 매번 떠 있는 힌트 중에 처음 한 번이면 되는 게 있나?
6. 툴팁에만 있는 필수 정보가 있나? 터치에서도 열리나?
